## Conceptos

Tres herramientas deshacen cambios, cada una para un momento distinto:

- **`git restore <archivo>`** descarta cambios sin confirmar en el
  working directory, volviendo el archivo a como estaba en el último
  commit. El cambio se pierde.
- **`git stash`** guarda temporalmente cambios sin confirmar, sin
  perderlos, para poder cambiar de rama o hacer otra cosa — y
  recuperarlos después con `git stash pop`.
- **`git revert <commit>`** deshace un commit ya confirmado (y quizás ya
  subido al remoto), creando un commit **nuevo** que aplica el cambio
  contrario. A diferencia de borrar el commit del historial, `revert` deja
  registro de que algo se deshizo, y por qué.

La pregunta que distingue cuál usar es: **¿el cambio ya está confirmado?**
Si no, `restore` (para descartarlo) o `stash` (para guardarlo). Si ya está
confirmado y compartido, `revert`.

## Cuándo usarlo

Usá `restore` cuando un cambio sin confirmar resultó ser un error y
querés volver atrás. Usá `stash` cuando el cambio sin confirmar todavía te
sirve, pero necesitás un working directory limpio para hacer otra cosa.
Usá `revert` cuando el commit a deshacer ya se compartió con el equipo —
reescribir el historial de un commit que otros ya tienen genera
problemas al resto del equipo.

## Buenas prácticas

- **Confirmar primero si el cambio ya está confirmado (committeado) o
  no**, antes de elegir la herramienta — esa pregunta decide todo lo que
  sigue.
- **Usar `git stash` en vez de `restore`** cuando el cambio sin confirmar
  todavía sirve, aunque sea temporalmente — `restore` lo descarta para
  siempre, sin vuelta atrás.
- **Preferir `revert` (nunca reescribir el historial) para deshacer un
  commit ya compartido** con el equipo — reescribir rompe las copias
  locales de quien ya tiene esos commits.
- **Revisar con `git log` cuál es exactamente el commit a revertir** antes
  de ejecutar `revert`, para no deshacer el cambio equivocado.
- **Avisar al equipo cuando se revierte algo ya compartido**, para que
  nadie se confunda al ver que un cambio "desapareció" sin explicación.

## Anti-patrones

- **Confundir `restore` con `stash`**: usar `restore` cuando el cambio en
  realidad todavía servía y había que guardarlo temporalmente — se pierde
  para siempre, sin poder recuperarlo.
- **Reescribir el historial de un commit ya compartido** en vez de usar
  `revert` — rompe el repositorio local de quien ya tiene esos commits.
- **Revertir el commit equivocado** por no revisar el historial antes —
  hay que confirmar con `git log` cuál es el commit correcto.
- **Dejar un `stash` guardado y olvidarse de él** — con el tiempo, nadie
  recuerda qué era ni por qué se había guardado.
