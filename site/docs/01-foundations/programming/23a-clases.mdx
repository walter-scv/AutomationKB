Las interfaces describen la forma de un dato. Una clase va un paso más allá: junta los datos con las operaciones que los modifican, protege lo que no se debe tocar desde afuera y permite crear varios objetos del mismo tipo, cada uno con su propio estado.

## Conceptos

Un objeto guarda datos, y las funciones operan sobre ellos. Cuando los
datos y las operaciones van siempre juntos, tenerlos separados trae dos
problemas. El primero es que nada impide modificar los datos sin pasar por
las funciones:

```ts
const cuenta = { numero: '001-4471', saldo: 5000 };

function depositar(cuenta: { saldo: number }, monto: number): void {
  if (monto > 0) {
    cuenta.saldo = cuenta.saldo + monto;
  }
}

depositar(cuenta, 2000);   // pasa por la validación
cuenta.saldo = -900;       // nada lo impide
```

El segundo es que, para crear otra cuenta, hay que volver a escribir la
forma del objeto y recordar qué funciones le corresponden. Una **clase**
resuelve las dos cosas: reúne en un solo lugar los datos de una entidad y
las operaciones que se pueden hacer con ellos, y permite crear tantos
objetos de ese tipo como hagan falta.

### Declarar una clase

```ts
class CuentaCorriente {
  numero: string;
  saldo: number;

  constructor(numero: string, saldoInicial: number) {
    this.numero = numero;
    this.saldo = saldoInicial;
  }

  depositar(monto: number): void {
    if (monto > 0) {
      this.saldo = this.saldo + monto;
    }
  }

  consultarSaldo(): number {
    return this.saldo;
  }
}
```

Las partes, de arriba abajo: el nombre de la clase, por convención con
mayúscula inicial. Las **propiedades**, con su tipo, como en una interface.
El **constructor**, una función especial que se ejecuta al crear cada
objeto y que deja las propiedades con su valor inicial. Y los **métodos**,
que son las funciones de la clase; se declaran sin la palabra `function`.

Dentro de la clase, **`this`** es el objeto sobre el que se está
trabajando. `this.saldo` es "el saldo de esta cuenta". Sin `this`, el
nombre `saldo` no se refiere a la propiedad, y TypeScript lo marca:

```text
error TS2663: Cannot find name 'saldo'. Did you mean the instance member 'this.saldo'?
```

### Crear objetos con `new`

La clase es el molde; cada objeto creado a partir de ella es una
**instancia**. Se crea con `new`, que ejecuta el constructor con los
argumentos indicados:

```ts
const cuentaDeAna = new CuentaCorriente('001-4471', 5000);
const cuentaDeLuis = new CuentaCorriente('001-9020', 0);

cuentaDeAna.depositar(2000);
cuentaDeAna.consultarSaldo();    // 7000
cuentaDeLuis.consultarSaldo();   // 0
```

Cada instancia tiene **sus propios valores**: depositar en la cuenta de
Ana no cambia la de Luis. Los métodos son los mismos para todas, pero cada
llamada trabaja sobre el objeto que está antes del punto.

Olvidar `new` es un error frecuente al empezar, y el mensaje lo sugiere:

```ts
const cuenta = CuentaCorriente('001-4471', 5000);
```

```text
error TS2348: Value of type 'typeof CuentaCorriente' is not callable. Did you mean to include 'new'?
```

### `private` y `readonly`: proteger los datos

Con la clase tal como está, `cuentaDeAna.saldo = -900` sigue siendo
posible. Los modificadores de acceso restringen quién puede tocar cada
propiedad. Una propiedad **`private`** solo se puede usar dentro de la
clase. Una propiedad **`readonly`** se asigna en el constructor y después
no se puede cambiar. Lo que no lleva modificador es **`public`**: accesible
desde cualquier lugar.

```ts
class CuentaCorriente {
  readonly numero: string;
  private saldo: number;
  // ... constructor y métodos iguales
}

const cuenta = new CuentaCorriente('001-4471', 5000);
cuenta.saldo = -900;
cuenta.numero = '001-0000';
```

```text
error TS2341: Property 'saldo' is private and only accessible within class 'CuentaCorriente'.
error TS2540: Cannot assign to 'numero' because it is a read-only property.
```

Ahora la única forma de cambiar el saldo es `depositar`, que valida el
monto. Ese es el sentido de `private`: que los datos solo cambien a través
de las operaciones que la clase ofrece, que son las que cuidan que el
objeto quede en un estado válido. Leer el saldo sigue siendo posible, a
través de `consultarSaldo()`.

### Propiedades declaradas en el constructor

Declarar una propiedad, recibirla en el constructor y asignarla con
`this.x = x` es tan habitual que TypeScript tiene una forma abreviada: si
un parámetro del constructor lleva un modificador (`private`, `readonly`,
`public`), se convierte automáticamente en propiedad:

```ts
class CuentaCorriente {
  constructor(readonly numero: string, private saldo: number) {}

  depositar(monto: number): void {
    if (monto > 0) {
      this.saldo = this.saldo + monto;
    }
  }
}
```

Es exactamente la misma clase de antes, con menos líneas. El cuerpo del
constructor queda vacío (`{}`) porque no hay nada más que hacer. Esta forma
es muy común en código real, así que conviene reconocerla.

### Propiedades con valor inicial

Una propiedad que siempre empieza con el mismo valor no necesita pasar por
el constructor: se le asigna el valor en la declaración, y TypeScript
infiere su tipo.

```ts
class CuentaCorriente {
  private movimientos: number[] = [];
  private bloqueada = false;
  // ...
}
```

### Heredar de otra clase

Igual que una interface puede extender a otra, una clase puede **heredar**
de otra con `extends`: tiene todo lo de la clase original y agrega lo
propio. El constructor de la clase hija tiene que llamar primero al de la
original con `super(...)`:

```ts
class CajaDeAhorro extends CuentaCorriente {
  constructor(numero: string, saldo: number, readonly tasaAnual: number) {
    super(numero, saldo);
  }
}

const ahorro = new CajaDeAhorro('002-3310', 10000, 0.3);
ahorro.depositar(500);   // método heredado de CuentaCorriente
ahorro.tasaAnual;        // 0.3, propio de CajaDeAhorro
```

Una clase también puede comprometerse a cumplir una interface con
`implements`: `class CuentaCorriente implements Cuenta { ... }`. Si le falta
alguna propiedad o método de la interface, TypeScript lo marca.

### Qué probar en una clase

Una clase guarda estado entre una llamada y otra, y eso cambia qué hay que
probar. Llamar a cada método una vez no alcanza. Los casos que aportan
información son las **secuencias**: depositar dos veces y comprobar que se
acumula; depositar un monto inválido y comprobar que el saldo no cambió
(una validación que falla no tiene que dejar el objeto a medio modificar).
También hay que comprobar la **independencia entre instancias**: operar
sobre una cuenta no tiene que afectar a otra. Y los **valores iniciales**:
qué devuelve `consultarSaldo()` en una cuenta recién creada, antes de
cualquier operación.

## Cuándo usarlo

Una clase conviene cuando hay datos que van siempre acompañados de las
mismas operaciones, y cuando hacen falta varias instancias de la misma
entidad con su propio estado. Para describir solo la forma de un dato, sin
comportamiento, alcanza con una interface.

## Buenas prácticas

- Marcar `private` lo que solo debe cambiar a través de los métodos.
- Marcar `readonly` lo que no cambia después de crear el objeto.
- Usar `this` para cada propiedad dentro de los métodos.
- Probar secuencias de llamadas y la independencia entre instancias.

## Anti-patrones

- **Propiedades públicas que cualquiera puede dejar en un valor inválido**.
- **Una clase sin métodos**, cuando una interface alcanzaba.
- **Probar cada método aislado**, sin secuencias.
