Con el entorno listo para ejecutar código, empezamos por lo más chico: qué
es una variable. Los fragmentos de esta lección se pueden probar en un
archivo `.ts`, como se vio en la lección anterior.

## Conceptos

### Qué es una variable

Un programa necesita guardar datos para usarlos después: el nombre de un
usuario, un total, si una opción está activada. Una **variable** es un
nombre que se asocia a un valor. Declararla crea ese nombre; asignarle un
valor hace que, a partir de ahí, el nombre represente ese valor:

```ts
const nombreDelCliente = 'Ana Gómez';
console.log(nombreDelCliente); // Ana Gómez
```

`console.log` muestra un valor en la consola, y se va a usar a lo largo de
estas lecciones para ver qué contiene una variable en cada momento.

### `const` y `let`

TypeScript declara variables con dos palabras: `const` y `let`. La
diferencia es si la variable se puede **reasignar**, es decir, hacer que
pase a representar otro valor.

`const` declara una variable que no se reasigna. Es la opción habitual,
porque la mayoría de los valores no cambian una vez calculados:

```ts
const iva = 0.21;
iva = 0.105;
```

```text
error TS2588: Cannot assign to 'iva' because it is a constant.
```

`let` declara una variable que sí puede cambiar. Se usa cuando el valor se
actualiza durante la ejecución, como un contador o un acumulador:

```ts
let paginaActual = 1;
paginaActual = paginaActual + 1;
console.log(paginaActual); // 2
```

Con `let` también se puede declarar la variable sin valor y asignarlo más
adelante, algo que con `const` no está permitido porque nunca se podría
asignar después:

```ts
let mensaje: string;
mensaje = 'Pedido confirmado';
```

`const` impide reasignar la variable, pero no impide modificar el
contenido de un objeto o un array que la variable guarde. La variable
sigue apuntando al mismo objeto; lo que cambia es una propiedad:

```ts
const pedido = {estado: 'pendiente'};
pedido.estado = 'pagado';          // válido: se modifica una propiedad
pedido = {estado: 'pagado'};       // error TS2588: se intenta reasignar la variable
```

`const` protege a qué valor apunta la variable, no el contenido de ese
valor. Esta diferencia vuelve a aparecer en las lecciones de arrays y
objetos.

Las variables declaradas con `const` y `let` existen solo dentro del
bloque (las llaves `{ }`) donde se declararon. Una variable creada dentro
de un `if` no se puede usar fuera de él. Esto se retoma en la lección de
funciones.

### Tipos básicos

El **tipo** indica qué clase de valor guarda una variable, y con eso qué
operaciones tienen sentido sobre ella. Los tres tipos básicos son:

- **`string`**, para texto. Se escribe entre comillas simples o dobles
  (`'Ana'` o `"Ana"`; esta guía usa simples). Con comillas invertidas se
  arman *template strings*, que permiten insertar valores con `${...}`:

  ```ts
  const nombre = 'Ana';
  const saludo = `Hola, ${nombre}`;   // 'Hola, Ana'
  ```

- **`number`**, para números, sin distinguir enteros de decimales: `30`,
  `1500.75` y `-2` son todos `number`. El separador decimal es el punto.

- **`boolean`**, que solo admite dos valores: `true` y `false`.

Hay además dos valores especiales que representan ausencia de valor:
**`undefined`**, que es el valor de una variable que todavía no recibió
ninguno, y **`null`**, que se asigna explícitamente para indicar "no hay
valor". Se encuentran, por ejemplo, al buscar algo que no existe; se ven en
detalle cuando aparecen en las lecciones siguientes.

Un tipo se puede escribir de forma explícita después del nombre, con dos
puntos:

```ts
const nombre: string = 'Ana';
const edad: number = 30;
const activo: boolean = true;
```

### TypeScript revisa los tipos antes de ejecutar

La razón de declarar tipos es que TypeScript revisa el código **antes de
que se ejecute**. Si un valor no coincide con su tipo, el error aparece al
escribir el código, en el editor, y no recién cuando un usuario usa el
programa:

```ts
const cantidad: number = '3';
```

```text
error TS2322: Type 'string' is not assignable to type 'number'.
```

El mensaje se lee de forma literal: se intentó asignar un valor de tipo
`string` (el texto `'3'`, entre comillas) a una variable declarada como
`number`. La corrección es usar el valor del tipo correcto, `3` sin
comillas. Los editores muestran estos errores subrayando el código y, al
posar el mouse encima, muestran el mensaje completo. Aprender a leerlos es
la forma más rápida de corregirlos: casi siempre dicen qué tipo se
esperaba y cuál se recibió.

### Tipo explícito o inferido

Escribir el tipo no siempre es necesario. Cuando el valor inicial deja
claro el tipo, TypeScript lo **infiere**:

```ts
const nombre = 'Ana';     // TypeScript infiere string
const edad = 30;          // infiere number
const activo = true;      // infiere boolean
```

La inferencia es igual de estricta que el tipo explícito: si después se
intenta asignar un texto a `edad`, el error aparece igual. Conviene
escribir el tipo cuando el valor inicial no alcanza para expresar la
intención: un array vacío no dice qué va a contener, y una variable sin
valor inicial no tiene de dónde inferir.

```ts
const codigosDePedido: string[] = [];   // un array de textos, vacío por ahora
let ultimoError: string;                // se asigna más adelante
```

### `any` desactiva la revisión

`any` le indica a TypeScript que no revise el tipo de un valor. Parece
cómodo, porque hace desaparecer los errores, pero lo que desaparece es la
protección:

```ts
const precio: any = '1500';
const conEnvio = precio + 800;
console.log(conEnvio); // '1500800'
```

Como `precio` es en realidad un texto, `+` lo concatena con 800 en lugar
de sumar. TypeScript no avisó nada porque se le pidió no revisar. Con el
tipo correcto, el problema aparece antes de ejecutar:

```ts
const precio: number = '1500';   // error TS2322: el valor tiene que ser un número
```

Cuando un dato llega de afuera sin tipo, por ejemplo al leer un archivo o
una respuesta de un servidor, la solución no es declararlo `any` sino
convertirlo o validarlo y darle su tipo real.

### `object` no describe la forma

`object` acepta cualquier objeto, pero no dice qué propiedades tiene. Por
eso TypeScript no permite usar ninguna:

```ts
const pagina: object = {titulo: 'Inicio', orden: 1};
console.log(pagina.titulo);
```

```text
error TS2339: Property 'titulo' does not exist on type 'object'.
```

Si se conoce la forma, se declara; o directamente se deja que TypeScript
la infiera del valor:

```ts
const pagina: {titulo: string; orden: number} = {titulo: 'Inicio', orden: 1};
const otraPagina = {titulo: 'Contacto', orden: 2};   // forma inferida
console.log(pagina.titulo, otraPagina.orden);       // válido
```

Las formas de los objetos se pueden nombrar para reutilizarlas, con
interfaces; se ve en su propia lección.

### Nombres

El nombre de una variable es la primera documentación que lee cualquiera
que use el código. En TypeScript la convención es **camelCase**: la primera
palabra en minúscula y las siguientes con mayúscula inicial
(`fechaDeVencimiento`, `cantidadDeCuotas`). Un buen nombre describe qué
contiene el valor, no su tipo ni su posición: `terminosAceptados` se
entiende solo; `dato1`, `valor` o `x` obligan a buscar en el resto del
código qué guardan. Para booleanos, un prefijo como `es`, `tiene` o
`puede` hace que el nombre se lea como una pregunta: `esMayorDeEdad`,
`tieneDescuento`.

## Cuándo usarlo

`const` es la opción por defecto; `let`, solo cuando el valor se reasigna.
Si no está claro, se empieza con `const`: si después hace falta reasignar,
TypeScript lo marca y se cambia a `let`. El tipo se escribe cuando la
inferencia no alcanza, y nunca se reemplaza por `any`.

## Buenas prácticas

- Usar `const` salvo que el valor se reasigne.
- Dejar que TypeScript infiera el tipo cuando el valor lo hace evidente, y
  escribirlo cuando no.
- Usar el tipo más preciso posible: nunca `any`, y no `object` cuando se
  conoce la forma.
- Elegir nombres en camelCase que describan el contenido.
- Leer el mensaje completo de cada error de tipos: dice qué se esperaba y
  qué se recibió.

## Anti-patrones

- **Declarar con `let` un valor que nunca se reasigna**.
- **Nombres genéricos** (`x`, `dato1`, `valor`).
- **Usar `any` para que desaparezcan los errores**.
- **Intentar reasignar una variable `const`**.
- **Usar `object` cuando se conoce la forma del valor**.
