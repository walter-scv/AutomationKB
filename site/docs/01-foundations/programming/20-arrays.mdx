## Conceptos

Un **array** es una lista ordenada de valores del mismo tipo:

```ts
const candidatos: string[] = [
  '',
  'Abcd123',
  'Abcd1234',
  'A'.repeat(64),
  'A'.repeat(65),
];
```

`string[]` significa "una lista de `string`". El array anterior agrupa los
cinco valores límite de la contraseña que se vienen usando en los capítulos
anteriores.

Cada elemento tiene una posición, llamada **índice**, que empieza en 0, no
en 1:

```ts
candidatos[0]; // '' (el primero)
candidatos[1]; // 'Abcd123'
candidatos[4]; // 'A'.repeat(65) (el último)
```

La propiedad `.length` da la cantidad total de elementos. Para el array de
arriba vale 5. El último índice válido es siempre `length - 1`:

```ts
const ultimo = candidatos[candidatos.length - 1];
```

Si se usa `length` como índice, se pide una posición que no existe y el
resultado es `undefined`:

```ts
candidatos[candidatos.length]; // undefined
candidatos[99];                // undefined
```

### Confirmar antes de acceder

Acceder a una posición solo es seguro si se sabe que el array tiene ese
elemento. Si el array puede estar vacío, hay que confirmarlo antes:

```ts
if (candidatos.length > 0) {
  const primero = candidatos[0];
  console.log(primero);
}
```

Sin esa confirmación, `candidatos[0]` devuelve `undefined` y cualquier
operación sobre ese valor falla más adelante, lejos del lugar donde se
originó el problema.

### Recorrer un array

`for...of` recorre todos los elementos sin manejar índices:

```ts
for (const candidato of candidatos) {
  console.log(candidato);
}
```

`filter` crea un array nuevo con los elementos que cumplen una condición:

```ts
const validos = candidatos.filter((candidato) => candidato.length >= 8);
```

`map` crea un array nuevo transformando cada elemento:

```ts
const longitudes = candidatos.map((candidato) => candidato.length);
```

`find` devuelve el primer elemento que cumple una condición, o `undefined`
si ninguno la cumple:

```ts
const primerValido = candidatos.find((candidato) => candidato.length >= 8);
```

`reduce` recorre el array y acumula un solo resultado:

```ts
const total = precios.reduce((acumulado, precio) => acumulado + precio, 0);
```

Ninguno de estos métodos modifica el array original: devuelven un
resultado y dejan la lista intacta. Eso es importante cuando el array se
sigue usando después.

Como `filter` y `map` devuelven un array nuevo, se puede llamar otro método
directamente sobre ese resultado. Eso se llama **encadenar**: cada paso
recibe lo que dejó el anterior. Por legibilidad, se suele escribir un
método por línea:

```ts
const longitudesValidas = candidatos
  .filter((candidato) => candidato.length >= 8) // 1. quedan solo los válidos
  .map((candidato) => candidato.length);        // 2. de cada uno, su longitud
```

El orden importa. Si primero se hiciera el `map`, quedaría una lista de
números y el `filter` ya no tendría las contraseñas para revisar. Y lo que
devuelve cada método define qué se puede hacer después: `find` y `reduce`
devuelven **un solo valor**, no un array, así que en general cierran la
cadena; `.length` también da un número, la cantidad de elementos.

Para copiar un array se usa el **spread** (`...`):

```ts
const copia = [...candidatos];
const conUnNuevo = [...candidatos, 'nuevo'];
```

La copia es superficial: si los elementos son objetos, las referencias a
esos objetos se comparten. Para este nivel alcanza con saber que el array
original no se toca.

Para agregar un elemento al final se usa `push`:

```ts
const nombres: string[] = [];
nombres.push('Ana');
nombres.push('Beto');
```

### Preguntar por el contenido: `includes`, `some` y `every`

Muchas veces no hace falta transformar un array sino responder una
pregunta sobre él. Tres métodos devuelven directamente un `boolean`:

```ts
const roles = ['lector', 'editor'];
roles.includes('editor');                         // true: ¿está este valor?

const montos = [1200, 300, 5400];
montos.some((monto) => monto > 5000);             // true: ¿al menos uno cumple?
montos.every((monto) => monto > 0);               // true: ¿todos cumplen?
```

`includes` compara con `===`, así que `[1, 2, 3].includes('2')` es
`false`. `some` y `every` reciben una función, igual que `filter`. Con un
array vacío, `some` devuelve `false` y `every` devuelve `true` ("todos los
elementos cumplen" es verdadero cuando no hay ninguno): un detalle que
conviene recordar al probar código que usa `every` para validar una lista.

### Ordenar: `sort` modifica el array

`sort` ordena los elementos, pero a diferencia de `filter` o `map`, **modifica
el array original**:

```ts
const apellidos = ['Ruiz', 'Gómez', 'Pérez'];
apellidos.sort();
console.log(apellidos);   // ['Gómez', 'Pérez', 'Ruiz']: el array original cambió
```

Además, sin argumentos, `sort` compara los elementos como texto, lo que da
un resultado inesperado con números:

```ts
const cantidades = [10, 9, 100];
cantidades.sort();
console.log(cantidades);   // [10, 100, 9]: ordenó como texto ('1' va antes que '9')
```

Para ordenar números se le pasa una función de comparación, y para no
alterar el original se ordena una copia:

```ts
const ordenadas = [...cantidades].sort((a, b) => a - b);   // [9, 10, 100]
```

La función recibe dos elementos y devuelve un número negativo si `a` va
antes, positivo si va después, o cero si da igual. `a - b` ordena de menor
a mayor; `b - a`, de mayor a menor.

Con texto, el `sort` sin argumentos compara por el código de cada
carácter: las mayúsculas quedan antes que las minúsculas, y las letras con
tilde, después de la z. Para ordenar como lo haría una persona se compara
con `localeCompare`, que devuelve el número negativo, positivo o cero que
espera `sort`:

```ts
const ciudades = ['tandil', 'Azul', 'Ávila', 'bahía'];
[...ciudades].sort();                                  // ['Azul', 'bahía', 'tandil', 'Ávila']
[...ciudades].sort((a, b) => a.localeCompare(b));     // ['Ávila', 'Azul', 'bahía', 'tandil']
```

### Qué probar en código que recibe un array

El código que trabaja con listas suele fallar en los mismos casos, y por
eso hay tres que conviene probar siempre: la lista **vacía** (¿el código
accede a `[0]` sin confirmar que existe?), la lista con **un solo
elemento** (¿el primero y el último coinciden y el código lo maneja?) y la
lista con **varios elementos** (¿se recorren todos, o un límite fijo deja
afuera algunos?). Para una función que calcula el promedio de las notas de
un alumno, por ejemplo, la lista vacía es el caso que más defectos revela:
dividir por `notas.length` cuando vale `0` da `NaN`.

### Cantidad fija o `.length`

Un loop no debería asumir cuántos elementos hay. Esto se rompe en cuanto el
array cambia de tamaño:

```ts
for (let i = 0; i < 3; i++) {
  revisar(candidatos[i]);
}
```

Si mañana hay cinco candidatos, dos quedan afuera; si hay dos, la tercera
vuelta usa `candidatos[2]`, que es `undefined`. `for...of` o
`i < candidatos.length` siguen al array real:

```ts
for (const candidato of candidatos) {
  revisar(candidato);
}
```

### Nombres: plural para listas

Una lista se nombra en plural (`candidatos`, `pedidos`, `usuarios`); un solo
elemento, en singular (`candidato`, `pedido`). Y el nombre tiene que decir
qué contiene: `candidatos` sirve; `lista` o `datos` obligan a mirar el
contenido para saber qué hay adentro.

### Un array no es un cajón de cosas sueltas

Un array mezcla valores que se recorren o se tratan igual. Si los datos son
de distinto tipo y cada posición significa otra cosa, no es un array: es un
objeto disfrazado.

```ts
const datos = ['ana@mail.com', 30, true]; // ¿qué es cada posición?
```

En cambio, un objeto le pone nombre a cada dato:

```ts
const usuario = {
  email: 'ana@mail.com',
  edad: 30,
  activo: true,
};
```

Los objetos se ven en detalle más adelante; por ahora alcanza con reconocer
cuándo un array está mezclando cosas que no comparten significado.

## Cuándo usarlo

Un array sirve cuando hay varios valores del mismo tipo que se van a tratar
de la misma forma — por ejemplo, varios valores de contraseña para
revisar con la misma lógica. Si solo hay un valor, o valores de tipos
distintos que no se relacionan entre sí, no hace falta un array: alcanza
con variables sueltas.

## Buenas prácticas

- Nombrar los arrays en plural.
- Usar `.length` para saber cuántos elementos tiene.
- Confirmar que el array no esté vacío antes de acceder a una posición puntual.
- Agrupar en un array solo valores del mismo tipo y la misma naturaleza.
- Elegir un nombre que describa qué contiene la lista.

## Anti-patrones

- **Nombrar un array en singular**.
- **Acceder a un índice sin saber si existe**.
- **Asumir una cantidad fija de elementos**.
- **Mezclar datos sin relación en un mismo array**.
