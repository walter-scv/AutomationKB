Ya sabés declarar variables tipadas y condicionales. El siguiente paso es
agrupar esa lógica bajo un nombre, para no repetirla cada vez que hace
falta.

## Conceptos

Una **función** agrupa código bajo un nombre para usarlo las veces que haga
falta sin repetirlo. Recibe **parámetros** (los valores que necesita, cada
uno con su tipo) y puede **devolver** un resultado con `return`:

```ts
function esContraseñaValida(contraseña: string): boolean {
  return contraseña.length >= 8 && contraseña.length <= 64;
}
```

`contraseña: string` es el parámetro. `: boolean` (después de los
paréntesis) declara qué tipo de valor devuelve la función. `return` es lo
que entrega ese resultado a quien la llamó.

La función no hace nada hasta que se la llama. Al llamarla, el resultado se
puede guardar o usar directamente:

```ts
const valida = esContraseñaValida('Abcd1234!'); // true
console.log(esContraseñaValida('corta'));       // false
```

### Parámetros y argumentos

Una función puede recibir varios parámetros. El orden importa: quien la
llama tiene que pasar los valores en el mismo orden en que se declaran.

```ts
function crearSaludo(nombre: string, hora: number): string {
  if (hora < 12) {
    return 'Buen día, ' + nombre;
  }
  return 'Buenas tardes, ' + nombre;
}

crearSaludo('Ana', 9);  // 'Buen día, Ana'
crearSaludo('Ana', 18); // 'Buenas tardes, Ana'
```

Cuando una función acumula demasiados parámetros sueltos del mismo tipo, es
fácil equivocarse de orden sin que TypeScript lo detecte. En ese caso
conviene agruparlos en un objeto:

```ts
function registrar(datos: {email: string; contraseña: string}): boolean {
  return datos.contraseña.length >= 8;
}
```

### El valor de retorno

`return` entrega un valor y termina la ejecución de la función en ese
punto. Si una función declara que devuelve `number`, todos los caminos
tienen que devolver un `number`:

```ts
function calcularTotal(precio: number, cantidad: number): number {
  return precio * cantidad;
}
```

Si falta el `return`, la función calcula el valor pero no lo entrega:

```ts
function calcularTotal(precio: number, cantidad: number): number {
  const total = precio * cantidad;
  // falta return: TypeScript marca que no devuelve nada
}
```

Si devuelve en un camino y en otro no, quien la llama recibe `undefined` en
el camino que faltó:

```ts
function clasificar(nota: number): string {
  if (nota < 4) {
    return 'Desaprobado';
  }
  // si nota >= 4, no hay return: devuelve undefined
}
```

La versión completa devuelve algo en todos los casos:

```ts
function clasificar(nota: number): string {
  if (nota < 4) {
    return 'Desaprobado';
  }
  return 'Aprobado';
}
```

Una función que busca algo puede no encontrarlo. En ese caso el tipo de
retorno contempla la ausencia de valor:

```ts
function buscarUsuario(id: string): Usuario | undefined {
  return usuarios.find((usuario) => usuario.id === id);
}
```

`Usuario | undefined` se lee como "un `Usuario`, o `undefined` si no se
encontró". `find` devuelve el primer elemento que cumple la condición, o
`undefined` cuando ninguno lo hace. Declarar esa posibilidad es parte de la
firma, no un detalle opcional.

El tipo declarado también tiene que coincidir con el valor devuelto. Esto es
un error de tipos, no un detalle de estilo:

```ts
function esMayor(edad: number): string {
  return edad >= 18; // Error: devuelve boolean, no string
}
```

### Funciones que no devuelven nada

Una función que solo hace algo (registrar un mensaje, enviar un evento) no
necesita devolver un valor. Se declara con `void`:

```ts
function registrarLog(mensaje: string): void {
  console.log(mensaje);
}
```

Sin `return`, la función igual termina y devuelve `undefined`, pero `void`
deja explícito que no hay un resultado que usar.

No confundas mostrar con devolver: `console.log` imprime un valor en la
consola para que lo veas vos, pero no se lo entrega a quien llamó a la
función. Si la función tiene que dar un resultado, va `return`:

```ts
function armarTitulo(nombre: string): string {
  console.log('Título: ' + nombre); // se ve en la consola, pero no se devuelve
  return 'Título: ' + nombre;       // esto es lo que recibe quien la llamó
}
```

### La misma función con otra sintaxis

Una función también se puede escribir como **arrow function**. Es la misma
idea, con otra forma:

```ts
const esContraseñaValida = (contraseña: string): boolean => {
  return contraseña.length >= 8 && contraseña.length <= 64;
};
```

Si el cuerpo es una sola expresión, se puede omitir `return` y las llaves:

```ts
const esContraseñaValida = (contraseña: string): boolean =>
  contraseña.length >= 8 && contraseña.length <= 64;
```

Las arrow functions aparecen todo el tiempo como callbacks de arrays y en
los tests; conviene reconocerlas aunque al principio escribas `function`.

### Alcance: lo que se declara adentro no sale

Una variable declarada dentro de una función existe solo mientras esa
función se ejecuta. No se puede usar desde afuera:

```ts
function calcularTotal(precio: number): number {
  const total = precio * 2;
  return total;
}

console.log(total); // Error: `total` no existe acá
```

Si el valor hace falta afuera, la función tiene que devolverlo con
`return`. Esa barrera evita que dos funciones se pisen variables con el
mismo nombre y hace más fácil razonar sobre cada una por separado.

### Una función, una responsabilidad

Si para describir la función hace falta un "y" ("valida la contraseña y
envía el formulario"), probablemente sean dos funciones. Separarlas permite
probarlas y reusarlas por separado.

El nombre también es parte de la función: `esContraseñaValida` dice qué
responde; `chequeo1` obliga a leer el cuerpo para saber qué hace.

### Dependencias y datos que se modifican

Una función debería recibir todo lo que necesita como parámetro, no depender
de una variable externa:

```ts
let descuento = 0;

function calcularTotal(precio: number): number {
  return precio - descuento; // depende de algo que no recibió
}
```

Si `descuento` cambia, la misma llamada da otro resultado. Pasarlo como
parámetro hace visible de qué depende:

```ts
function calcularTotal(precio: number, descuento: number): number {
  return precio - descuento;
}
```

Tampoco conviene modificar el objeto o array que se recibió. Quien llamó a
la función puede seguir usándolo y no espera que cambie por abajo:

```ts
function agregarPedido(pedidos: string[], pedido: string): string[] {
  pedidos.push(pedido); // modifica el array recibido
  return pedidos;
}
```

Devolver uno nuevo evita ese efecto:

```ts
function agregarPedido(pedidos: string[], pedido: string): string[] {
  return [...pedidos, pedido];
}
```

### Cuando una función se llama mal

TypeScript compara cada llamada con la firma de la función: cuántos
parámetros recibe y de qué tipo es cada uno. Si no coinciden, el error
aparece antes de ejecutar. Con `crearSaludo(nombre: string, hora: number)`:

```ts
crearSaludo(9, 'Ana');
```

```text
error TS2345: Argument of type 'number' is not assignable to parameter of type 'string'.
```

El mensaje se refiere al primer argumento: se pasó un `number` donde la
firma espera un `string`. Los argumentos se asignan a los parámetros por
posición, así que invertir el orden es un error de tipos cuando los tipos
difieren. Si faltan argumentos, el mensaje es otro:

```ts
crearSaludo('Ana');
```

```text
error TS2554: Expected 2 arguments, but got 1.
```

Cuando dos parámetros tienen el mismo tipo, invertirlos no produce ningún
error, porque los dos tipos coinciden. `calcularTotal(cantidad, precio)` en
lugar de `calcularTotal(precio, cantidad)` compila sin quejas. Esa es la
razón de agrupar en un objeto los parámetros del mismo tipo cuando son
varios: con nombres, el orden deja de importar.

### Parámetros opcionales y valores por defecto

Un parámetro puede ser opcional, marcado con `?`. Si no se pasa, vale
`undefined`, y la función tiene que contemplarlo:

```ts
function formatearPrecio(monto: number, moneda?: string): string {
  if (moneda === undefined) {
    return `$${monto}`;
  }
  return `${moneda} ${monto}`;
}

formatearPrecio(1500);          // '$1500'
formatearPrecio(1500, 'USD');   // 'USD 1500'
```

Cuando hay un valor razonable para el caso en que no se pasa nada, es más
simple declarar un **valor por defecto**:

```ts
function formatearPrecio(monto: number, moneda: string = '$'): string {
  return `${moneda} ${monto}`;
}
```

Los parámetros opcionales y con valor por defecto van al final de la lista:
como los argumentos se asignan por posición, uno opcional en el medio
obligaría a pasar algo en su lugar.

### Probar una función

Una función que solo depende de sus parámetros y devuelve un valor tiene
una propiedad muy útil para testear: con las mismas entradas, siempre da
la misma salida. Probarla consiste en elegir entradas y comparar lo que
devuelve con lo esperado, como en cualquier caso de prueba:

```text
esContraseñaValida('Abcd123')         → false   (7 caracteres, debajo del mínimo)
esContraseñaValida('Abcd1234')        → true    (8, el mínimo)
esContraseñaValida('A'.repeat(64))    → true    (64, el máximo)
esContraseñaValida('A'.repeat(65))    → false   (65, encima del máximo)
```

Una función que lee una variable de afuera o modifica lo que recibe pierde
esa propiedad: el resultado depende de algo más que sus parámetros, y la
misma prueba puede dar resultados distintos. Esa es la consecuencia
práctica de las reglas de la sección anterior: una función que depende
solo de sus parámetros se puede probar de forma aislada y repetible.

## Cuándo usarlo

Cualquier lógica que se vaya a usar más de una vez conviene envolverla en
una función, en vez de copiar y pegar el mismo código cada vez. También
conviene usar una función para nombrar una operación: `esContraseñaValida(contraseña)`
dice qué hace, mientras que la condición repetida en cada lugar donde se
necesita no lo dice por sí sola.

## Buenas prácticas

- Una función hace una sola cosa.
- Nombrar la función con un verbo que describa qué hace o qué pregunta responde.
- Declarar el tipo de cada parámetro y del valor de retorno.
- Usar solo lo que la función recibió como parámetro.
- Devolver un valor nuevo en vez de modificar el que se recibió.

## Anti-patrones

- **Olvidarse del `return`**.
- **Copiar y pegar la misma lógica**.
- **Depender de una variable externa**.
- **Modificar el objeto que se recibió como parámetro**.
- **Demasiados parámetros sueltos del mismo tipo**.
