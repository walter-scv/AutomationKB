Ya sabés comparar valores con operadores. El siguiente paso es usar esa
comparación para decidir qué bloque de código ejecutar.

## Conceptos

`if (condición) { ... } else { ... }` ejecuta un bloque u otro según si la
condición es verdadera o falsa. Nunca se ejecutan los dos:

```ts
if (contraseña.length >= 8 && contraseña.length <= 64) {
  resultado = 'Contraseña válida';
} else {
  resultado = 'Contraseña inválida';
}
```

La condición se evalúa como verdadera o falsa. Para que el código sea
claro, conviene que sea una expresión booleana (`edad >= 18`, `esValida`),
no un valor de otro tipo que JavaScript interpreta como verdadero o falso.
Si es `true`, entra al primer bloque; si es `false`, al `else`.

### `else if` para más de dos resultados

Cuando hay más de dos casos posibles, se encadena con `else if`. Las
condiciones se evalúan en orden y se ejecuta la primera que sea verdadera:

```ts
if (nota < 4) {
  resultado = 'Desaprobado';
} else if (nota <= 7) {
  resultado = 'Aprobado';
} else {
  resultado = 'Promocionado';
}
```

El orden importa. Con `nota = 3`, la primera condición ya es verdadera y las
siguientes no se evalúan. Si se invirtiera el orden y `nota <= 7` fuera
primero, un `3` caería en "Aprobado" aunque debería estar desaprobado.

Los valores justo en el borde de cada condición son los que más se
confunden. Acordate de la entrada anterior: `<` y `>` son estrictos (el
valor del límite **no** cumple la condición), mientras que `<=` y `>=`
incluyen el propio valor. Para saber en qué rama cae un número que está
justo en un límite, mirá el operador de esa condición, no solo el número.

Un `else if` que repite una condición ya cubierta no aporta nada:

```ts
if (esValida) {
  guardar();
} else if (!esValida) {
  mostrarError(); // el else de abajo ya cubría este caso
} else {
  mostrarError();
}
```

Alcanza con `if (esValida) { ... } else { ... }`: si la primera condición es
falsa, el `else` ya sabe que `!esValida` es verdadero.

### Anidar o combinar

Un `if` dentro de otro funciona, pero muchas veces se puede aplanar. Si las
dos condiciones tienen que cumplirse, se combinan con `&&`:

```ts
// Anidado
if (usuario) {
  if (usuario.activo) {
    permitirAcceso();
  }
}

// Más directo
if (usuario && usuario.activo) {
  permitirAcceso();
}
```

Si los casos son alternativas (rangos de una nota, por ejemplo), conviene
`else if` en vez de un `if` anidado dentro del `else`. La lectura baja un
nivel y queda claro que solo se ejecuta una rama.

### Ramas que no hacen nada

Una rama `else` vacía se puede borrar:

```ts
if (esValida) {
  guardar();
} else {
  // nada: no hay nada que hacer si no es válida
}
```

Si no hay nada que hacer en el caso falso, el `else` sobra. Dejarlo sugiere
que ahí pasa algo, y obliga a leerlo para descubrir que no.

### `if/else` solo para asignar un booleano

Si el único objetivo es asignar `true` o `false`, la comparación ya devuelve
ese booleano:

```ts
let esMayor = false;
if (edad >= 18) {
  esMayor = true;
} else {
  esMayor = false;
}
```

Se reemplaza por una sola línea:

```ts
const esMayor = edad >= 18;
```

Además de ser más corto, evita la variable mutable y deja la condición a la
vista.

### Condiciones negadas

Una condición negada obliga a leer el `else` para entender el caso normal:

```ts
if (!esInvalida) {
  guardar();
} else {
  mostrarError();
}
```

Si existe la versión positiva, es más directo invertirla:

```ts
if (esValida) {
  guardar();
} else {
  mostrarError();
}
```

Negar tiene sentido cuando el caso excepcional es el que se quiere destacar
primero, pero no cuando solo agrega un `!` y un `else` para compensarlo.

### Ternario: un `if/else` que devuelve un valor

Cuando las dos ramas solo eligen un valor, se puede usar el **operador
ternario**:

```ts
const mensaje = edad >= 18 ? 'adulto' : 'menor';
```

Se lee: si la condición es verdadera, toma el valor antes de `:`; si es
falsa, el de después. Es equivalente a un `if/else` que asigna en cada rama,
pero en una sola expresión.

Conviene usarlo solo para decisiones cortas. Anidar varios ternarios hace
que la condición sea difícil de leer; en ese caso, `if/else if` es más
claro.

### `switch`: un valor contra varias opciones

Cuando una misma variable se compara contra una lista de valores
concretos, `switch` lo expresa de forma más ordenada que una cadena de
`else if`:

```ts
switch (metodoDePago) {
  case 'tarjeta':
    cobrarConTarjeta();
    break;
  case 'transferencia':
    mostrarDatosBancarios();
    break;
  case 'efectivo':
    generarCuponDePago();
    break;
  default:
    mostrarError('Método de pago no soportado');
}
```

Cada `case` compara `metodoDePago` con un valor usando `===`. El `break`
termina el `switch`: si se omite, la ejecución sigue con el `case`
siguiente aunque no coincida, un error frecuente que se nota porque se
ejecutan dos acciones. `default` cubre cualquier valor no previsto y
cumple el mismo papel que el `else` final.

### Salir temprano

Cuando una función tiene que verificar varias condiciones antes de hacer su
trabajo, anidarlas empuja la lógica principal hacia la derecha y la vuelve
difícil de seguir:

```ts
function confirmarReserva(reserva: Reserva) {
  if (reserva.fecha) {
    if (reserva.personas <= 8) {
      if (hayDisponibilidad(reserva)) {
        guardar(reserva);
      }
    }
  }
}
```

La alternativa es resolver primero los casos que impiden continuar y
salir de la función con `return` (las funciones se ven en la lección
siguiente). Estas comprobaciones al principio se llaman **cláusulas de
guarda**:

```ts
function confirmarReserva(reserva: Reserva) {
  if (!reserva.fecha) return;
  if (reserva.personas > 8) return;
  if (!hayDisponibilidad(reserva)) return;

  guardar(reserva);
}
```

Las dos versiones hacen lo mismo, pero en la segunda cada condición se lee
sola y la acción principal queda al final, sin anidamiento.

### Cada rama es un caso de prueba

Un condicional define caminos distintos, y cada camino es un
comportamiento que hay que probar. Esta cadena define el descuento según
la cantidad de unidades compradas:

```ts
if (unidades < 3) {
  descuento = 0;
} else if (unidades <= 9) {
  descuento = 0.1;
} else {
  descuento = 0.2;
}
```

Tiene tres ramas, así que necesita al menos un caso por rama. Y como cada
condición tiene un límite, conviene probar los valores en los bordes, que
es donde un `<` escrito en lugar de un `<=` cambia el resultado:

```text
unidades = 2    → primera rama           (sin descuento)
unidades = 3    → borde: segunda rama    (10%), porque 3 < 3 es falso
unidades = 9    → borde: segunda rama    (10%), porque 9 <= 9 es verdadero
unidades = 10   → tercera rama           (20%)
```

Es la misma idea de la cobertura de ramas y de boundary value analysis del
bloque de Testing, aplicada al leer el código: quien entiende qué ramas
tiene un condicional sabe qué casos no pueden faltar.

## Cuándo usarlo

Cualquier decisión que dependa del valor de una condición (un número, un
texto, un booleano) usa `if`. Cuando hay más de dos caminos posibles,
`else if` evita anidar `if` dentro de `if` — cada nivel de anidación extra
hace más difícil seguir la lógica de un vistazo.

## Buenas prácticas

- Mantener las condiciones simples y legibles.
- Usar `else if` para más de dos casos, en vez de anidar.
- Asignar directamente el resultado de una comparación.
- Evitar condiciones negadas cuando se pueda invertir el orden de las ramas.
- No dejar una rama `else` que no hace nada.

## Anti-patrones

- **Anidar `if` dentro de `if` dentro de `if`**.
- **Usar `if/else` solo para asignar `true`/`false`**.
- **Negar una condición sin necesidad**.
- **Repetir casi la misma condición en un `if` y en el `else if` siguiente**.
