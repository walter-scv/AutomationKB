## Conceptos

Un **loop** repite un bloque de código. La forma más directa de recorrer un
array es `for...of`, que repite el bloque una vez por cada elemento:

```ts
for (const contraseña of candidatos) {
  console.log(contraseña);
}
```

`while` repite el bloque mientras una condición sea verdadera. Se usa
cuando no se sabe de antemano cuántas veces hay que repetir:

```ts
let intentos = 0;
while (intentos < 3) {
  console.log('Intentando...');
  intentos = intentos + 1;
}
```

Para que un `while` termine, algo adentro del bloque tiene que poder volver
falsa la condición. En el ejemplo, `intentos` aumenta en cada vuelta hasta
llegar a 3. Si nada la cambia, el loop no termina nunca:

```ts
let intentos = 0;
while (intentos < 3) {
  console.log('Intentando...'); // intentos nunca cambia
}
```

### La condición puede ser falsa desde el principio

Si la condición ya es falsa antes de entrar, el cuerpo no se ejecuta ni una
vez. Eso no es un error de TypeScript: el programa sigue, pero el loop no
hizo nada.

```ts
let pendientes = 0;
while (pendientes > 0) {
  procesarSiguiente();
  pendientes = pendientes - 1;
}
```

Con `pendientes = 0`, la condición es falsa y `procesarSiguiente()` nunca se
llama. Si la intención era procesar al menos una vez, hay que revisar el
valor inicial o usar un `do...while`.

### `for` con índice

Cuando hace falta el número de posición, se usa el `for` clásico:

```ts
for (let i = 0; i < candidatos.length; i++) {
  console.log(i, candidatos[i]);
}
```

Si no se necesita el índice, `for...of` es más corto y evita el error de
quedarse corto o pasarse con el límite:

```ts
for (const candidato of candidatos) {
  revisar(candidato);
}
```

Si hacen falta el índice y el valor, `entries()` devuelve un par por cada
elemento:

```ts
for (const [indice, nombre] of nombres.entries()) {
  console.log(indice, nombre);
}
```

El `const [indice, nombre]` separa el par en dos variables: la posición y el
valor.

### Las tres partes de un `for` clásico

El `for` con índice tiene tres partes entre paréntesis, separadas por
punto y coma, y cada una se ejecuta en un momento distinto:

```ts
for (let i = 0; i < precios.length; i++) {
  console.log(i, precios[i]);
}
```

`let i = 0` se ejecuta **una sola vez**, antes de empezar. `i <
precios.length` se evalúa **antes de cada vuelta**: si es verdadera, se
ejecuta el cuerpo; si es falsa, el loop termina. `i++` se ejecuta **al
final de cada vuelta**. Con `precios = [1200, 300, 5400]`, el recorrido es:

```text
i = 0   → 0 < 3 es verdadero → muestra 0 1200 → i pasa a 1
i = 1   → 1 < 3 es verdadero → muestra 1 300  → i pasa a 2
i = 2   → 2 < 3 es verdadero → muestra 2 5400 → i pasa a 3
i = 3   → 3 < 3 es falso     → el loop termina
```

Seguir así un loop, vuelta por vuelta, es la forma de entender qué hace
cuando el resultado no es el esperado. El error clásico es la condición
`i <= precios.length`: agrega una vuelta con `i = 3`, y `precios[3]` es
`undefined`.

### `do...while`

`do...while` ejecuta el cuerpo al menos una vez y recién después evalúa la
condición:

```ts
let intentos = 0;
do {
  intentos = intentos + 1;
} while (intentos < 3);
```

Es útil cuando la primera ejecución tiene que ocurrir sí o sí, por ejemplo
para pedir un dato antes de poder validarlo.

### `break` y `continue`

`break` corta el loop por completo; `continue` salta a la siguiente vuelta:

```ts
for (const candidato of candidatos) {
  if (candidato === '') {
    continue; // salta este elemento
  }
  if (candidato.length > 64) {
    break; // no sigue revisando
  }
  revisar(candidato);
}
```

Cuidado con `continue` en un `while`: si salta la línea que modifica la
condición, el loop puede quedar infinito:

```ts
let i = 0;
while (i < 3) {
  if (i === 2) {
    continue; // i nunca cambia: loop infinito
  }
  i = i + 1;
}
```

En ese caso hay que incrementar antes del `continue` o reordenar el bloque.

### Modificar el array mientras se recorre

Cambiar un array con `for...of` mientras se lo recorre puede saltear
elementos, porque el índice interno se mueve al mismo tiempo que la lista
cambia:

```ts
for (const pedido of pedidos) {
  if (pedido.cancelado) {
    pedidos.splice(pedidos.indexOf(pedido), 1);
  }
}
```

En el ejemplo, `indexOf` devuelve la posición del pedido y `splice` lo quita
del array. Si hay que filtrar, `filter` devuelve un array nuevo sin tocar el
original:

```ts
const pedidosActivos = pedidos.filter((pedido) => !pedido.cancelado);
```

### Patrones habituales

La mayoría de los loops responden a uno de unos pocos patrones. **Acumular**
combina todos los elementos en un resultado, que empieza en un valor neutro:

```ts
let total = 0;
for (const precio of precios) {
  total += precio;
}
```

**Contar** suma uno cada vez que un elemento cumple una condición:

```ts
let vencidos = 0;
for (const turno of turnos) {
  if (turno.fecha < hoy) {
    vencidos++;
  }
}
```

**Buscar y cortar** recorre hasta encontrar lo que se busca y sale con
`break`, sin revisar el resto:

```ts
let primerSinStock = undefined;
for (const producto of productos) {
  if (producto.stock === 0) {
    primerSinStock = producto;
    break;
  }
}
```

Los tres tienen un equivalente entre los métodos de arrays (`reduce`,
`filter(...).length` y `find`), y cuando existe, el método suele ser más
corto y más claro. El loop explícito sigue siendo útil cuando la lógica de
cada vuelta es más compleja que una sola condición.

### Qué probar en un loop

Los defectos de los loops aparecen casi siempre en los extremos, y por eso
hay tres casos que no pueden faltar. **Cero vueltas:** ¿qué pasa si la
lista está vacía, o si la condición ya es falsa al empezar? El acumulador
tiene que quedar en su valor inicial y el código posterior tiene que
tolerarlo. **Una vuelta:** con un solo elemento se ven los errores de
límites, como empezar en 1 en lugar de 0. **Varias vueltas:** confirma que
el loop recorre todos los elementos y que termina; un `while` que nunca
termina se manifiesta como un programa que no responde.

## Cuándo usarlo

`for...of` conviene cuando ya existe la lista completa de valores a
recorrer (como el array de contraseñas candidatas). `while` conviene
cuando la cantidad de repeticiones depende de algo que se descubre
durante la ejecución (por ejemplo, reintentar algo hasta que funcione, sin
saber de antemano cuántos intentos va a necesitar).

## Buenas prácticas

- Usar `for...of` para recorrer un array completo.
- En un `while`, confirmar que algo dentro del bloque cambia la condición.
- Usar `entries()` cuando además del valor hace falta la posición.
- Reservar `while` para cuando la cantidad de vueltas se descubre durante
  la ejecución.
- Extraer a una función el cuerpo de un loop que crece mucho.

## Anti-patrones

- **Loop infinito**: nada dentro del bloque cambia la condición.
- **Modificar el array que se está recorriendo**.
- **Usar un índice manual para recorrer un array completo**, cuando
  `for...of` hace lo mismo sin riesgo de pasarse del límite.
