La primera capa del framework concentra el conocimiento de cada pantalla en una clase. Es el patrón más difundido de la automatización de UI, y el que más tiempo ahorra cuando la aplicación cambia.

## Conceptos

### El problema que resuelve

Dos tests del ingreso de la biblioteca, sin ningún patrón:

```ts
// ingreso-correcto.spec.ts
await page.goto('/ingresar');
await page.getByLabel('Email').fill('lucia@biblio.test');
await page.getByLabel('Contraseña').fill('clave123');
await page.getByRole('button', { name: 'Ingresar' }).click();

// ingreso-incorrecto.spec.ts, en otro archivo, repite lo mismo
await page.goto('/ingresar');
await page.getByLabel('Email').fill('lucia@biblio.test');
await page.getByLabel('Contraseña').fill('otra');
await page.getByRole('button', { name: 'Ingresar' }).click();
```

El día que el botón pase a decir «Entrar», o el campo a llamarse
«Correo», hay que buscar esas líneas en cada test que ingresa. Con cien
tests, son cien lugares.

### La idea: una clase por pantalla

Un **Page Object** es una clase que concentra cómo se interactúa con una
pantalla. Los tests le piden que haga cosas y nunca tocan el DOM:

```ts
// sin Page Object: el test sabe cómo está armada la pantalla
await page.getByLabel('Email').fill('lucia@biblio.test');
await page.getByLabel('Contraseña').fill('clave123');
await page.getByRole('button', { name: 'Ingresar' }).click();

// con Page Object: el test dice qué quiere lograr
await ingreso.ingresar('lucia@biblio.test', 'clave123');
```

La clase, en su forma mínima (con clases de TypeScript, entrada de
clases):

```ts
import { type Page, type Locator } from '@playwright/test';

export class IngresoPage {
  readonly email: Locator;
  readonly clave: Locator;
  readonly botonIngresar: Locator;
  readonly error: Locator;

  constructor(private readonly page: Page) {
    this.email = page.getByLabel('Email');
    this.clave = page.getByLabel('Contraseña');
    this.botonIngresar = page.getByRole('button', { name: 'Ingresar' });
    this.error = page.getByText('Email o contraseña incorrectos');
  }

  async abrir(): Promise<void> {
    await this.page.goto('/ingresar');
  }

  async ingresar(email: string, clave: string): Promise<void> {
    await this.email.fill(email);
    await this.clave.fill(clave);
    await this.botonIngresar.click();
  }
}
```

- El **constructor** recibe la `page` del test y arma los locators. Como
  un locator no busca nada hasta que se usa (entrada de locators
  orientados al usuario), se pueden crear todos al principio.
- Los **locators** son propiedades `readonly`: se leen desde afuera, pero
  nadie los reemplaza.
- Los **métodos** son lo que una persona hace en esa pantalla: abrirla,
  ingresar.

Si el botón cambia de texto, se corrige en una línea de esta clase y los
cien tests quedan arreglados sin tocarlos.

### Usar el Page Object en un test

El test crea el Page Object con su `page` y lo usa:

```ts
import { test, expect } from '@playwright/test';
import { IngresoPage } from '../pages/IngresoPage';
import { PrestamosPage } from '../pages/PrestamosPage';

test.describe('Ingreso', () => {
  test('con datos correctos llega a sus préstamos', async ({ page }) => {
    const ingreso = new IngresoPage(page);
    const prestamos = new PrestamosPage(page);
    await ingreso.abrir();
    await ingreso.ingresar('lucia@biblio.test', 'clave123');
    await expect(prestamos.titulo).toBeVisible();
  });

  test('con una contraseña incorrecta muestra el error', async ({ page }) => {
    const ingreso = new IngresoPage(page);
    await ingreso.abrir();
    await ingreso.ingresar('lucia@biblio.test', 'otra');
    await expect(ingreso.error).toBeVisible();
  });
});
```

```text
  ✓  2 [chromium] › tests/ingreso.spec.ts:8:7 › Ingreso › con datos correctos llega a sus préstamos (162ms)
  ✓  3 [chromium] › tests/ingreso.spec.ts:16:7 › Ingreso › con una contraseña incorrecta muestra el error (126ms)
```

Los dos Page Objects comparten la misma `page`: son dos formas de mirar
la misma pestaña, una por pantalla. Crear los Page Objects a mano en cada
test es repetitivo; las fixtures lo resuelven (entrada de fixtures y
BaseTest).

### El Page Object no verifica

La regla más importante del patrón: **las assertions van en el test**. El
Page Object devuelve lo necesario para verificar (un locator, un texto, un
número) y el test decide si es correcto:

```ts
// así no: el Page Object decide qué está bien
async verificarError(): Promise<void> {
  await expect(this.error).toBeVisible();
}

// así sí: el Page Object expone el elemento, el test verifica
await expect(ingreso.error).toBeVisible();
```

Si el Page Object verifica, el test deja de mostrar qué se espera, y el
mismo método no sirve para un test que espera lo contrario (que el error
**no** aparezca).

### Métodos con significado y parámetros

Cada método se nombra por lo que logra en el negocio, no por lo que hace
técnicamente: `ingresar(email, clave)`, no `completarCamposYClickear()`;
`renovar(libro)`, no `clickBotonDeFila()`. Y recibe como parámetro lo que
no sabe de antemano, como cualquier función (entrada de funciones). La
pantalla de préstamos tiene un método por cada cosa que se hace o se
pregunta:

```ts
export class PrestamosPage {
  readonly titulo: Locator;
  readonly mensaje: Locator;

  constructor(private readonly page: Page) {
    this.titulo = page.getByRole('heading', { name: 'Mis préstamos' });
    this.mensaje = page.getByRole('status');
  }

  prestamo(tituloLibro: string): Locator {
    return this.page.getByRole('listitem').filter({ has: this.page.getByRole('heading', { name: tituloLibro }) });
  }

  async renovar(tituloLibro: string): Promise<void> {
    await this.prestamo(tituloLibro).getByRole('button', { name: 'Renovar' }).click();
  }

  vencimiento(tituloLibro: string): Locator {
    return this.prestamo(tituloLibro).getByText(/^Vence el/);
  }
}
```

`prestamo(libro)` y `vencimiento(libro)` devuelven locators, para que el
test los use con una assertion web-first; `renovar(libro)` es una acción.
Ninguno expone cómo está armada la lista: el test escribe
`prestamosPage.renovar('Rayuela')`.

### El tamaño justo

Un Page Object modela **una pantalla**, o una parte grande y repetida de
varias (como un menú). No modela un flujo completo: un método
`reservarRenovarYDevolver()` mezcla tres acciones que el test tiene que
poder combinar y verificar por separado. Si un método hace tanto que el
test ya no dice qué pasa, es un test escondido dentro del Page Object.

## Cuándo usarlo

En cuanto dos tests interactúan con la misma pantalla. En una suite real,
cada pantalla que se prueba tiene su Page Object.

## Buenas prácticas

- Un Page Object por pantalla, con sus locators como propiedades.
- Métodos con nombre de negocio, que reciben como parámetro lo que varía.
- Devolver locators o valores, y dejar las assertions en el test.
- Mantener los métodos chicos, para que el test siga contando el caso.

## Anti-patrones

- **Assertions dentro del Page Object.**
- **Métodos técnicos** como `clickBoton1()` o `llenarCampos()`.
- **Un Page Object gigante** para toda la aplicación.
- **Métodos que encadenan un flujo entero**, con verificaciones en el
  medio.
