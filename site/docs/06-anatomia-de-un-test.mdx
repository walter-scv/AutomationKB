# Anatomía de un test

## Lo mínimo que tiene que tener un test

Sin ninguna estructura, un test es una lista de instrucciones sueltas:
difícil de leer, y difícil de saber dónde termina la preparación y empieza
lo que realmente se está probando. La estructura mínima que resuelve esto
se conoce como **AAA**:

```ts
test('clicking Buy increases units owned', async ({ page }) => {
  // ARRANGE — preparar lo necesario
  const dashboardPage = new DashboardPage(page);
  await dashboardPage.navigate();

  // ACT — hacer la acción que se quiere probar
  await dashboardPage.fillQuantity(1);
  await dashboardPage.clickBuy();

  // ASSERT — verificar el resultado
  expect(await dashboardPage.getUnitsOwned()).toBe(1);
});
```

**Arrange** prepara el escenario, **Act** hace la acción, **Assert**
verifica el resultado. Si un test no se puede dividir así de limpio, casi
siempre está probando más de una cosa a la vez — y debería ser dos tests,
no uno.

## De Arrange/Act a una Page Object

Fijate que el Arrange y el Act de arriba nunca tocan un selector: todo pasa
por `dashboardPage`. Eso no es casualidad. Sin eso, se verían así:

```ts
// ARRANGE/ACT sin Page Object
await page.goto('/dashboard');
await page.locator('input[name="quantity"]').fill('1');
await page.getByRole('button', { name: 'Buy' }).click();
```

Funciona — pero el selector del botón queda escrito acá, y en cualquier
otro test que también compre algo. El día que el botón cambie de texto o
de estructura, hay que encontrar y arreglar esa línea en cada test que la
repite. Una **Page Object** es la clase que concentra ese conocimiento en
un solo lugar, para que ningún test tenga que repetirlo:

```ts
class DashboardPage {
  readonly buyButton = this.page.getByRole('button', { name: 'Buy' });
  constructor(private page: Page) {}
  async clickBuy() { await this.buyButton.click(); }
}
```

*(Versión mínima — la clase real tiene más métodos, como los de la tabla
de abajo.)* Ahora el selector vive en un solo lugar, y el test ya no lo ve
— solo le pide a `dashboardPage` que haga cosas. La estructura AAA no
cambió: el Arrange sigue preparando y el Act sigue actuando, solo que
ahora lo hacen a través de la Page Object, nunca tocando la pantalla
directo. Estos son los métodos que vas a usar más abajo:

## Qué hace bueno a un assert

Ya viste que Arrange y Act no deberían tocar la pantalla directo. Un
**Assert** mal escrito comete el mismo error, de tres formas distintas.
Estas son las tres reglas que vas a aplicar en la actividad:

**Regla 1. El assert no toca la pantalla directamente.** Es la misma idea
de arriba: si necesitás un dato de la pantalla, se lo pedís a la Page
Object — nunca armás tu propio locator dentro del assert.

<Compare
  bad={{
    code: `const units = await page.locator('p', { hasText: 'Units' }).textContent();`,
    explanation: 'El test arma su propio locator en vez de usar un método que ya existe en la Page Object.',
  }}
  good={{
    code: `const units = await dashboardPage.getUnitsOwned();`,
    explanation: 'La Page Object ya sabe encontrar ese dato — el test solo lo pide.',
  }}
/>

**Regla 2. El assert no calcula.** Sacar palabras de un texto, convertirlo
a número o sumar montos es trabajo de la Page Object — igual que armar el
locator era su trabajo en la regla 1. El test solo compara.

<Compare
  bad={{
    code: `const text = await dashboardPage.unitsLabel.textContent();
const units = parseInt(text.replace('Units: ', ''));`,
    explanation: 'Usa un locator de la Page Object (no rompe la regla 1), pero convierte el texto a mano.',
  }}
  good={{
    code: `const units = await dashboardPage.getUnitsOwned();`,
    explanation: 'La Page Object ya devuelve el número listo — el test no convierte nada.',
  }}
/>

**Regla 3. Se compara contra un valor calculado, nunca contra un número
fijo.** Esta regla ya no es sobre la pantalla, sino sobre contra qué
comparás. Si hoy tenés 10 unidades y escribís `toBe(11)`, el test pasa una
vez. Mañana, con 11 unidades, falla aunque la app funcione bien.

<Compare
  bad={{
    code: `expect(await dashboardPage.getUnitsOwned()).toBe(11);`,
    explanation: '11 es el número de hoy. Con otra cantidad inicial, el test falla aunque la app funcione bien.',
  }}
  good={{
    code: `const unitsBefore = await dashboardPage.getUnitsOwned();
// ...compra...
expect(await dashboardPage.getUnitsOwned()).toBe(unitsBefore + 1);`,
    explanation: 'Compara contra el punto de partida medido, no contra un número fijo.',
  }}
/>
